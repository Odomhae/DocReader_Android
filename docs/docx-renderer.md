# M6. DOCX 렌더러 선택 근거

- 확인일: 2026-10-07
- 선택: **docx-preview 0.4.1** (+ 의존성 JSZip 3.10.2)

## 선택 근거

| 항목 | docx-preview |
|---|---|
| 라이선스 | Apache-2.0 (허용 목록에 있음) |
| 최신 상태 | npm 최신 버전 0.4.1, 레지스트리 최종 수정 2026-09-21 |
| 의존성 | JSZip 하나. JSZip은 MIT 또는 GPL-3.0 이중 라이선스이며 **MIT로 사용**한다 |
| 번들 크기 | docx-preview 76KB + JSZip 98KB (minified) |
| 출력 | 쪽 단위 HTML. 표, 그림, 머리글/바닥글, 각주를 그린다 |
| 오프라인 | 네트워크 요청이 없다. 그림은 `blob:` URL로 넣는다 |

검토한 다른 후보:

- **mammoth.js** (BSD-2-Clause): 문서를 의미 중심의 단순 HTML로 바꾼다. 쪽 구분, 머리글/바닥글을 버리므로 M6 완료 기준(머리글/바닥글 렌더링)을 만족할 수 없다.

## 제약

- **WebView 80 이상이 필요하다.** 배포본이 ES2020 문법(`?.`, `??`)을 쓴다. API 26 에뮬레이터의 WebView 69에서는 스크립트 파싱부터 실패하므로, HWP와 같은 방식으로 버전을 확인해 업데이트 안내를 보여준다. 80이라는 숫자는 문법 지원 시점에서 나온 것이고, 실제로 확인한 지점은 69(차단됨)와 133(렌더링됨)뿐이다.
- 문서 전체를 한 번에 DOM으로 만든다. HWP 뷰어처럼 보이는 쪽만 그리지 않으므로 아주 긴 문서에서는 느리거나 메모리를 많이 쓸 수 있다. 측정하지 않았다.
- 쪽 나눔은 문서에 저장된 쪽 나눔 정보와 명시적 쪽 나누기에 의존한다. 워드에서 본 것과 쪽 수가 다를 수 있다.
- 쪽은 실제 크기(A4는 약 794 CSS px)로 조판한 뒤 화면 폭에 맞게 축소한다.

## 확인한 것 (API 36 에뮬레이터, WebView 133)

`samples/`의 DOCX 6개가 렌더링된다: 기본 텍스트, 표, 그림, 머리글/바닥글, 여러 쪽(6쪽), 표+그림+머리글+바닥글. 손상된 DOCX는 오류 화면과 "다른 앱으로 열기"가 나온다. 쪽 이동, 문서 내 검색, 회전·프로세스 종료 후 쪽 복원도 확인했다.

샘플은 모두 직접 만든 단순한 문서다. 워드로 만든 실제 문서(스타일, 번호 매기기, 도형, 차트 등)는 확인하지 않았다.
