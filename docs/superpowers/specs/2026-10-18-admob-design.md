# AdMob 광고 추가 설계

- 작성일: 2026-10-18
- 상태: 구현됨 (2026-10-18). 구현하며 바뀐 점은 맨 아래 "구현하며 바뀐 점"에 있다.

## 목표

척척문서(Readily)에 Google AdMob 광고를 넣는다. 광고 위치는 네 곳이다.

1. 홈 화면 아래 배너
2. 설정 화면 아래 배너
3. 앱 오프닝 광고
4. 홈에서 뒤로가기를 누르면 뜨는 종료 팝업 안의 300×250 광고

문서를 읽는 뷰어 화면에는 광고를 넣지 않는다.

## 바뀌는 원칙과 바뀌지 않는 원칙

- **인터넷 권한**: 앱에 `INTERNET` 권한이 생긴다. 인터넷은 광고에만 쓴다.
- **오프라인 동작은 유지**: 앱은 인터넷 없이도 모든 기능이 동작한다. 오프라인이면 광고만 나오지 않는다. 그래서 스토어 문구 "인터넷 없이 동작"은 그대로 쓴다.
- **문서는 기기 밖으로 나가지 않는다**: 뷰어 WebView의 외부 네트워크 차단(`ViewerUrls.isInternal`, asset 로더 밖 요청 403)과 그 계측 테스트는 바꾸지 않는다. 뷰어 모듈은 광고 모듈에 의존하지 않는다.
- **라이선스 규칙 예외**: 의존성은 Apache-2.0, MIT, BSD만 허용한다는 규칙은 유지한다. 예외로 Google Mobile Ads SDK와 Google User Messaging Platform(UMP) SDK 두 개만 허용하고, 이 사실을 Guide.md와 `docs/THIRD_PARTY.md`에 기록한다. 두 SDK는 Google의 자체 약관을 따른다.
- **배포 국가**: 전 세계. EEA·영국 사용자에게는 UMP로 광고 동의를 받는다 (Google EU 사용자 동의 정책, 2024-01-16부터 Google 인증 CMP 필수).

## 모듈 구조

새 모듈 `:core:ads`(Android 라이브러리, Hilt)를 만든다.

```
:app ───────────┐
:feature:home ──┼──► :core:ads ──► Google Mobile Ads SDK, UMP SDK
:feature:settings┘
:viewer:* ──────────► (의존하지 않음)
```

의존 방향 규칙(`app → feature / viewer → core`)을 그대로 따른다. `settings.gradle.kts`, CLAUDE.md와 Guide.md의 모듈 목록에 추가한다. assets를 쓰게 되면 최상위 폴더는 `ads/`로 한다.

### 구성 요소

| 이름 | 역할 | 사용하는 곳 |
|---|---|---|
| `AdsConsent` | 앱 시작 시 UMP로 동의 정보를 갱신하고, 필요하면 동의 팝업을 띄운다. 그 뒤 `MobileAds`를 초기화한다. 광고를 요청해도 되는지(`canRequestAds`)와 개인정보 옵션 항목이 필요한지를 `StateFlow`로 내보낸다. | `:app`(`MainActivity`), `:feature:settings` |
| `AppOpenAdController` | 오프닝 광고를 불러오고, 보여줄 조건이 맞으면 보여준다. | `:app` |
| `ExitAdLoader` | 종료 팝업용 300×250 광고를 앱 시작 시 미리 불러와 들고 있는다. 실패하면 다시 시도한다. | `:app`, `:feature:home` |
| `BannerAd` Composable | 화면 폭에 맞춘 적응형 고정 배너. | `:feature:home`, `:feature:settings` |
| `ExitDialog` Composable | 종료 확인 팝업. 광고가 있으면 위에 넣고, 없으면 광고 자리 없이 그린다. | `:feature:home` |
| `AdPolicy` (순수 함수) | 오프닝 광고와 종료 팝업을 보여줄지 판단한다. 단위 테스트 대상. | 위 컨트롤러들 |

모든 광고 요청은 `canRequestAds`가 참일 때만 한다.

## 광고별 동작

### 앱 오프닝 광고

- **띄우는 때**: 런처 아이콘으로 앱을 새로 실행했고(`ACTION_MAIN` + `CATEGORY_LAUNCHER`, 저장된 상태 없음), 그 시점에 광고가 이미 로드돼 있을 때만.
- **기다리지 않는다**: 스플래시를 유지하거나 로딩 화면을 두지 않는다. 로드돼 있지 않으면 건너뛴다. 홈이 보인 뒤에 늦게 로드된 광고를 띄우지 않는다 (AdMob 정책: 광고가 갑자기 나타나 콘텐츠를 가리면 안 된다).
- **띄우지 않는 때**: 처음 설치한 뒤 첫 실행. 다른 앱에서 파일을 열고 들어온 경우(`ACTION_VIEW`). 화면 회전. 백그라운드에서 복귀(권한 설정 화면, 공유 시트, "다른 앱으로 열기"에서 돌아오는 경우 포함).
- **알려진 결과**: 새 실행 직후에는 광고가 아직 로드되지 않은 경우가 대부분이라 노출이 매우 적다. 사용자가 이 점을 알고 선택했다.
- 첫 실행 여부는 DataStore에 저장한다.

### 홈·설정 화면 배너

- 화면 맨 아래에 적응형 고정 배너(anchored adaptive banner)를 둔다.
- 로드되기 전이나 실패하면 높이 0으로 자리를 차지하지 않는다.
- 설정 화면에 "개인정보 옵션" 항목을 추가한다. UMP가 필요하다고 할 때(EEA·영국)만 보이고, 누르면 UMP 개인정보 옵션 양식을 연다.

### 종료 팝업

- **미리 로드**: 앱 시작 시(`AdsConsent` 초기화 직후) 300×250(`MEDIUM_RECTANGLE`) 광고를 불러온다. 실패하면 다시 시도한다. 횟수와 간격은 구현 계획에서 정한다.
- **띄우는 때**: 런처로 들어온 상태에서 홈 화면 뒤로가기. 지금 홈에는 따로 처리하는 뒤로가기 동작이 없으므로(검색어가 있어도 바로 앱을 나간다) 홈의 뒤로가기는 모두 이 팝업으로 간다.
- **띄우지 않는 때**: 다른 앱에서 파일을 열고 들어와 뷰어에서 뒤로가기를 누르면 팝업 없이 보낸 앱으로 돌아간다.
- **배치**: 광고는 팝업 위쪽, 문구 "앱을 종료할까요?"와 "취소"·"종료" 버튼은 아래쪽. 버튼은 광고와 붙지 않게 간격을 둔다 (AdMob 300×250 가이드: 종료 확인 화면의 닫기 버튼 옆에 광고를 두면 안 된다).
- **광고가 없을 때**: 오프라인, 보여줄 광고 없음, 동의 거부 등. 광고 자리 없이 같은 문구와 버튼만 있는 팝업을 띄운다. 뒤로가기 동작이 항상 같다.
- 팝업에서 광고를 보여준 뒤에는 다음 종료를 위해 새 광고를 다시 불러온다.

## 광고 ID

- 디버그 빌드: Google이 공개한 테스트 앱 ID와 테스트 광고 단위 ID.
- 릴리스 빌드: 실제 AdMob 앱 ID와 광고 단위 ID 세 개(오프닝, 배너, 종료 팝업 300×250). 비밀 정보가 아니므로 `:core:ads`의 빌드 타입별 리소스(`src/release/res`)에 둔다.
- 실제 ID는 사용자가 AdMob 콘솔에 앱을 등록한 뒤 받는다. 릴리스 빌드에 테스트 ID가 남아 있으면 빌드가 실패하도록 Gradle 검사를 둔다.

## 매니페스트

- `INTERNET`, `ACCESS_NETWORK_STATE`를 추가한다.
- `com.google.android.gms.ads.APPLICATION_ID` 메타데이터를 추가한다.
- `com.google.android.gms.permission.AD_ID`는 SDK 매니페스트 병합으로 들어온다.

## 실패 처리

- 광고 로드나 표시 실패를 사용자에게 오류로 보여주지 않는다. 배너는 자리를 차지하지 않고, 오프닝 광고는 건너뛰고, 종료 팝업은 광고 없이 뜬다.
- 광고 실패는 열기 실패와 달리 사용자가 알 필요가 없으므로, "예외를 삼키지 않는다" 규칙의 예외로 Guide.md에 적는다. 로그에는 광고 오류 코드만 남긴다.
- UMP 동의 확인이 실패하면 광고를 요청하지 않는다. 앱 기능은 그대로 동작한다.

## 테스트

- 단위 테스트: `AdPolicy`의 판단 로직.
  - 오프닝 광고: 실행 경로(런처 / `ACTION_VIEW`), 새 실행 여부, 첫 실행 여부, 로드 상태, `canRequestAds`
  - 종료 팝업: 진입 경로, 광고 유무
- 첫 실행 기록을 저장하는 리포지토리에도 단위 테스트를 쓴다.
- SDK가 실제로 광고를 보여주는지는 테스트 광고로 기기에서 확인해야 한다. 2026-10-13부터 에뮬레이터가 부팅되지 않으므로 실제 폰이 필요하다. 확인하지 못하면 그렇게 보고한다.
- 기존 `:viewer:web` 네트워크 차단 계측 테스트가 계속 통과해야 한다.

- **CLAUDE.md**: "앱에 `INTERNET` 권한이 없다" 문장 수정, 모듈 목록에 `:core:ads`, 광고 구조 요약.
- **Guide.md**: 오프라인 원칙의 범위(문서·뷰어), 라이선스 예외, 광고 실패 처리 예외, 모듈 목록.

## 구현하며 바뀐 점

- **SDK**: 기존 Google Mobile Ads SDK(`play-services-ads` 25.5.0)는 유지보수 모드라서, Google이 권장하는 GMA Next-Gen SDK(`ads-mobile-sdk` 1.5.0)와 UMP 4.0.0을 썼다. 두 SDK 모두 minSdk 24 이하다. Next-Gen SDK는 콜백을 백그라운드 스레드에서 호출한다.
- **미리 로드**: `ExitAdLoader`를 따로 만들지 않고 SDK의 `AppOpenAdPreloader`와 `BannerAdPreloader`를 썼다. SDK 초기화 직후 한 번 시작하면, 꺼낸 뒤 보충, 실패 시 재시도, 만료 전 교체를 SDK가 한다. 공식 문서가 직접 재시도하지 말라고 한다. 버퍼는 위치마다 1개다.
- **종료 팝업이 뜨는 때**: 다른 앱에서 파일을 열고 들어와도 뷰어 아래에 홈이 있어서, 뷰어에서 뒤로가기를 누르면 보낸 앱이 아니라 홈으로 간다. 그래서 "외부에서 들어오면 팝업 없음" 규칙은 필요 없고, 홈에서 뒤로가기를 누르면 항상 팝업이 뜬다.
- **첫 실행**: `:core:data`의 `LaunchHistoryRepository`가 프로세스가 시작될 때 기록한다. 첫 실행 프로세스 동안에는 오프닝 광고를 띄우지 않는다 (공식 문서: "앱을 처음 시작할 때 앱 오프닝 광고를 표시하지 마세요").
- **오프닝 광고가 실제로 뜨는 경우**: 콜드 스타트에는 미리 로드된 광고가 없다. 프로세스가 살아 있는 상태에서 액티비티를 새로 만들 때(예: 종료 팝업으로 나간 뒤 아이콘으로 다시 실행) 뜬다.
- **테스트 ID 검사**: `assembleRelease`까지 막으면 실제 ID를 받기 전에는 로컬에서 릴리스 빌드를 시험할 수 없어서, Play에 올리는 `bundleRelease`만 막는다.
- **종료 팝업 광고의 테스트 ID**: 고정 크기 배너 테스트 ID(`/6300978111`)를 300×250 크기로 요청한다.

## 변경: 오프닝 광고 노출 확대 (2026-10-18)

처음 설계대로면 오프닝 광고가 거의 뜨지 않아서, 사용자 결정으로 두 가지를 더했다.

- **콜드 스타트 대기**: 런처로 새로 실행하면 `androidx.core:core-splashscreen`(1.2.0, Apache-2.0)으로 스플래시를 최대 2초 유지하며 광고를 기다린다. 그 안에 로드되면 보여주고, 아니면 건너뛴다. 홈이 보인 뒤에 늦게 온 광고는 띄우지 않는다. 사용자가 처음에 3초 대기를 거절해서 2초로 정했다. 콜드 스타트에서는 초기화와 첫 로드가 2초 안에 끝나지 않을 때가 많다.
- **백그라운드 복귀**: 앱이 백그라운드에 갔다가(`ProcessLifecycleOwner` ON_STOP) 돌아오면(`onResume`) 미리 로드된 광고가 있을 때 바로 보여준다.
- **공통 제외**: 첫 실행 세션, 다른 앱이 문서를 넘긴 경우, 앱이 직접 연 다른 앱 화면(권한 설정, 공유 시트, 다른 앱으로 열기)에서 돌아온 경우, 마지막 오프닝 광고 뒤 30분 이내. 앱이 직접 연 화면은 `MainActivity.startActivityForResult` 오버라이드로 감지한다.
- 이 변경으로 위 "앱 오프닝 광고"의 "기다리지 않는다", "백그라운드에서 복귀 시 띄우지 않음"은 더 이상 맞지 않는다.
